# GitHub Product Semantics

1. Identify the root user or system problem behind the GitHub concept.
2. Gather current official GitHub evidence or direct product observation; label inference separately.
3. Separate GitHub facts from this platform's target contract.
4. Extract only durable mechanisms: actors, principals, resources, ownership, relationships, state transitions, authorization, and collaboration loops.
5. Test whether the concept is a necessary entity, a relationship, a state, a view, or merely a UI convention.
6. Remove Git-specific assumptions unless the no-code collaboration model independently requires them.
7. Map the result to the invariant that Repository is a no-code collaboration container.
8. Propose the smallest test that could disprove the adaptation.

Never use GitHub's existence of a feature as sufficient justification for adding it here.
