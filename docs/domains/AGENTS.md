# Domain Documentation Scope

- Do not create a domain merely to fill a folder or mirror GitHub terminology.
- Each domain must state the problem it owns, owner, boundary, entities, relationships, invariants, states, permissions, events, dependencies, unknowns, and discriminating tests.
- Distinguish actors, principals, contexts, resources, and relationships.
- Use one canonical term per concept and define aliases only when external compatibility requires them.
- Cross-domain dependencies must state direction, contract, and failure behavior.
- Domain documents describe target semantics; implementation mapping belongs elsewhere.
